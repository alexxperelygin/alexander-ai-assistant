## Ближайшие шаги (рекомендуемый порядок)

1. **Запустить worker на постоянной основе** (VPS/Railway/Docker) и накапливать
   снапшоты ≥2–4 недели.
2. Еженедельно запускать backtest по горизонтам; следить за rug rate и unclosable.
3. Подключить Helius (free tier) — реальное число держателей и скорость их роста.
4. Подключить Telegram-уведомления (токен в .env).

## Среднесрочно

- Birdeye-ключ → исторический датасет → train/validation/out-of-sample калибровка
  весов скоринга (см. BACKTEST_METHODOLOGY).
- Социальный модуль: Farcaster API (бесплатный), при бюджете — X API; метрики
  уникальности авторов и бот-детекция.
- Кластеризация кошельков (funding-графы через Helius) для insider-детекции.
- Persist очередь (BullMQ + Redis), горизонтальное масштабирование сканера.
- PostgreSQL в production (ADR-1).

## Долгосрочно

- Мультисеть: Base, Ethereum, BNB Chain — через те же интерфейсы провайдеров.
- Полуавтоматическое исполнение (подготовленная транзакция, подписывает пользователь) —
  только после подтверждённого edge; полного автотрейдинга в планах нет до
  устойчивого out-of-sample результата.
- ML-модель поверх собранного датасета (после того, как простые правила измерены).
