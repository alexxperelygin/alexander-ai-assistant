## Что используется в MVP

- **Discovery**: GeckoTerminal `GET /networks/solana/new_pools`.
- **Market**: DexScreener `GET /latest/dex/tokens/{mint}` (самый ликвидный пул).
- **Risk**: RugCheck `GET /v1/tokens/{mint}/report` (кэш 10 минут).
- **Исполнимость**: Jupiter `GET /swap/v1/quote` в обе стороны — подтверждение
  продаваемости и реальный price impact; `GET /price/v3` для цены SOL.

## Правила работы с источниками

1. Каждый вызов проходит через `fetchJson` с таймаутом, throttle и записью в
   `SourceHealth` (ошибки видны на странице System Health).
2. Отказ источника не валит цикл: признак становится null, попадает в `dataGaps`,
   confidence снижается, при нехватке ядра данных статус — DATA_UNAVAILABLE.
3. Mock-режим (`DATA_MODE=mock`) полностью изолирован и помечается в БД и UI.

## GoPlus Security (EVM)

Бесплатно, без ключа, лимит ~30 запросов/мин. Закрывает для Base, BNB Chain,
Ethereum и Arbitrum то же, что RugCheck закрывает для Solana: honeypot,
`cannot_sell_all`, доп-эмиссия (`is_mintable`), остановка переводов
(`transfer_pausable`), налоги на покупку/продажу, открытость исходников,
скрытый владелец, возврат прав владения, концентрация держателей, блокировка LP.

Важная деталь разбора: поля приходят строками `"0"` / `"1"` / `""`. Пустая
строка означает «источник не смог проверить» — она превращается в «нет данных»,
а не в «безопасно». Продажа считается подтверждённой, только когда источник
ЯВНО ответил, что токен не honeypot.

Доли (`percent`) приходят в виде 0..1, а не процентов. Контракты пулов и локеры
исключаются из подсчёта концентрации — иначе почти любой токен выглядит как
предельно сконцентрированный (та же ошибка, что уже ловили в RugCheck).

## X (Twitter) API v2 — платный, опциональный

Включается ключом `X_BEARER_TOKEN`. Без ключа провайдер возвращает null, и
система работает ровно как раньше — никаких заглушек и выдуманных чисел.

Экономика источника определяет всю конструкцию. Базовый тариф даёт порядка
10 000 прочитанных постов в **месяц**, то есть ~330 в день. Опрашивать ими
десятки тысяч токенов невозможно, поэтому:

* запрос делается только по токенам, дошедшим до CANDIDATE или READY
  (десятки в день), и не чаще раза в час на токен;
* поиск идёт **по адресу контракта**, а не по тикеру: тикеры совпадают у сотен
  токенов, адрес уникален — выборка чистая без ручной разметки;
* расход считается по факту прочитанных постов, месячный потолок задаётся
  `X_MONTHLY_POST_BUDGET`; при исчерпании снимок сохраняется с ошибкой вместо
  тихого перерасхода.

Собираются не только упоминания: уникальные авторы, суммарная аудитория,
вовлечённость, медианный возраст аккаунтов и доля аккаунтов моложе 30 дней.
Причина — накрутка: десять упоминаний от старых аккаунтов с аудиторией и
десять от аккаунтов, созданных вчера, это разные события, а по одному счётчику
упоминаний они неразличимы.

Данные **не входят в скоринг** до проверки предсказательной силы в исследовании.

## Reddit (бесплатно, требует регистрации приложения)

Ключи `REDDIT_CLIENT_ID` / `REDDIT_CLIENT_SECRET`, тип приложения «script»,
авторизация client_credentials. С 2023 года анонимный доступ к `.json` отдаёт
403 — проверено; обходить это запрещено заданием и означало бы бан по IP
сервера, где работают другие приложения владельца.

Ограничение источника: возраст аккаунта автора требует отдельного запроса на
каждого автора, то есть десятков запросов на токен. Поэтому поля возраста и
охвата остаются `null` — «не знаем», а не «ботов нет». Окно в один час
фильтруется на нашей стороне: API умеет сужать выдачу только сутками.

## Farcaster через Neynar (есть бесплатный уровень)

Ключ `NEYNAR_API_KEY`. Открытый узел сети (hub) отвечает без ключа — проверено,
HTTP 200, — но умеет только отдать пост по идентификатору; полнотекстового
поиска, который нам нужен для адреса контракта, в нём нет.

Охват считается по авторам, а не по постам: десять постов одного автора с
900 подписчиками — это охват 900, а не 9000.
