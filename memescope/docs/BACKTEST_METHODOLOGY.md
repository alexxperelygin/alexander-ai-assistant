# Backtest Methodology

Код: `src/lib/backtest/`. Запуск: страница Backtests или `npm run backtest`.

## Определение результата

Классы исхода на горизонтах **1ч, 6ч, 24ч, 3д, 7д**:

| Класс | Определение |
| --- | --- |
| +50% / 2x / 5x | чистая доходность после издержек достигла порога |
| −50% | чистая доходность ≤ −50% |
| rug | ликвидность упала ниже 20% от уровня на входе в пределах горизонта |
| unclosable | выход не симулируется (нет forward-данных или неизвестна ликвидность) |

«Успех» стратегии определяется не классами по отдельности, а **expectancy > 0 после
издержек и лучше baseline** (см. вердикты ниже).

## Модель издержек (каждая сделка, вход и выход)

- комиссия DEX 0.25%;
- сетевой + priority fee $0.05;
- price impact: наблюдаемый из котировки Jupiter, иначе `size/(liq/2 + size)`
  (константное произведение, односторонняя глубина);
- дрейф задержки 0.3% в неблагоприятную сторону;
- fill отклоняется, если ликвидность неизвестна (не «бесплатное» исполнение).

## Контроль bias

| Bias | Мера |
| --- | --- |
| Look-ahead | вход — последний снапшот **до** сигнала; исход — только снапшоты **после**; точка позже дедлайна горизонта не используется (покрыто тестами) |
| Survivorship | вселенная — все обнаруженные токены, включая умершие/rug; baseline «купить всё подряд» использует ту же вселенную |
| Мнимая точность | горизонт засчитывается только при наблюдении во второй половине окна; иначе null, не экстраполяция |
| Подгонка | пороги зафиксированы до накопления данных; train/validation/test по времени — обязательный шаг перед любой калибровкой весов (см. ниже) |
| Малые выборки | < 20 сигналов → статус NO_DATA без метрик |

## Метрики

signals, evaluable, win rate, expectancy (средняя чистая доходность), median return,
profit factor, max drawdown (equity последовательных сделок), rug rate, доля
незакрываемых, разбивка по месяцам; всё — для стратегии и baseline.

## Вердикты (честность обязательна)

- `NO_DATA` — выборка мала, выводов нет;
- `NO EDGE` — expectancy ≤ 0 после издержек, либо не лучше baseline;
- `PRELIMINARY EDGE` — лучше baseline, но прямо помечается как требующий больше
  данных и out-of-sample подтверждения.

Система **никогда** не называет себя прибыльной без устойчивого out-of-sample результата.

## Текущее ограничение и план исследования

Система тестирует **свои собственные** сигналы на данных, которые сама накапливает
(forward-testing). Это исключает look-ahead по построению, но требует времени.

Полный исторический тест по чужим прошлым токенам требует платного источника
исторических OHLCV/трейдов (Birdeye). План при подключении ключа:

1. выгрузить выборку токенов за ≥3 месяца (успешные и погибшие);
2. восстановить признаки на момент листинга+N минут (только тогда доступные);
3. разделить по времени: train / validation / out-of-sample test;
4. сравнить с baseline'ами (купить всё; купить топ-объём);
5. калибровать пороги на train, проверить на test, отчёт по месяцам и режимам рынка;
6. только после этого менять веса скоринга.
